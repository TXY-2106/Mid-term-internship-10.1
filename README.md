# 中期实习 10.1 ｜ 排队 / 服务需求监测器

> UL–LICHPU 智慧校园生活实验室 · 学生项目 · 15 ECTS · 12 周实施周期
>
> 当前阶段：早期 —— 选题已确认，具体服务区域、需求与技术方案待定

## 1. 项目概要

**校园问题**

食堂取餐、图书馆借阅与咨询台、学生服务中心、打印点、咖啡档口等服务窗口在高峰时段容易排队，使用者无法提前判断等待情况；服务方也难以实时掌握需求分布。

**项目任务**

- 匿名感知选定服务区域的排队长度或服务需求
- 估算等待状态（空闲 / 正常 / 拥挤，或预计等待分钟数）
- 通过本地显示屏与网页仪表板实时发布，并保留历史数据

**用户与受益者**

- 直接用户：等待服务的学生与教职工 —— 减少盲目等待
- 受益方：服务点管理方 —— 掌握需求分布，用于排班与引导

**核心交付**：集成可工作原型 + 实时等待状态显示 + 仪表板 + 对照基准的验证证据

**不在范围内**：个人身份识别、人脸 / 步态识别、考勤或执法用途、对校方排班的自动化决策

## 2. 验收标准

| 编号 | 验收项 | 标准 | 验证方式 |
| --- | --- | --- | --- |
| A1 | 排队长度估计 | 设计密度范围内误差 ≤ ±1 人 | 与人工计数同时段对照，重复 ≥ 5 次 |
| A2 | 等待状态判定 | 对照人工观测准确率 ≥ 80% | 覆盖空闲 / 正常 / 高峰三类场景 |
| A3 | 端到端延迟 | 现场变化到显示更新 ≤ 5 秒 | 秒表与系统日志时间戳比对 |
| A4 | 稳定性 | 连续运行 ≥ 4 小时无崩溃 | 长时运行记录 |
| A5 | 隐私合规 | 无摄像头、无人脸或身份识别，仅保存聚合计数 | 方案与数据审查 |
| A6 | 集成原型 | 至少 2 个有意义的数据输入，端到端可工作 | 现场演示 |
| A7 | 测试证据 | 单元 / 集成 / 系统测试对照需求，有记录 | 测试记录与数据集 |
| A8 | 仪表板 | 实时状态 + 历史曲线 + 告警机制 | 现场演示 |
| A9 | 跨国复制 | 说明 UL 与 LICHPU 部署的差异与可行性 | 报告章节 |

> 上述阈值需在需求关口前与教员确认后固化，并细化为可测试的需求条目。
