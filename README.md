# 中期实习 10.1 ｜ 排队 / 服务需求监测器

> UL–LICHPU 智慧校园生活实验室 · 学生项目 · 15 ECTS · 12 周实施周期
>
> 当前阶段：方案已确定，进入采购与原型搭建（红外线识别 + STM32 边缘采集 + ESP32 联网）

## 1. 项目概要

**校园问题**

食堂取餐、图书馆借阅与咨询台、学生服务中心、打印点、咖啡档口等服务窗口在高峰时段容易拥挤，使用者无法提前判断等待情况；服务方也难以实时掌握需求分布。

**项目任务**

- 匿名感知选定服务区域的进出人流、在场人数与排队长度分级
- 按在场人数与队列分级判定拥挤状态（空闲 / 正常 / 拥挤）
- 通过网页仪表板实时发布当前状态与历史曲线，并提供阈值告警
- 本地保存原始计数数据，实验结束后导出，用于对照分析

**技术方案（已确定）**

| 环节 | 方案 |
| --- | --- |
| 感知 | E18-D80NK 红外光电开关 ×4：2 路置于通道两侧，比较触发先后判定进 / 出；2 路沿队列方向置于约 50% 与 100% 位置，作队列长度阈值检测。不使用摄像头，不采集可见光图像 |
| 边缘采集 | STM32F103C8T6：1 kHz 定时采样、进出计数、队列分级、DS3231 离线时间戳、microSD 原始日志 |
| 联网与展示 | ESP32（CH340）：经 UART 接收数据，Wi-Fi 上报并托管网页仪表板 |
| 供电 | 5V/3A |

**数据流**

```
E18 进出 ×2 ─┐
             ├─► STM32 ──SPI──► microSD（原始日志）
E18 队列 ×2 ─┘      │
                    ├──I²C──► DS3231（离线时间戳）
                    └──UART──► ESP32 ──Wi-Fi──► 网页仪表板
```

**队列分级规则**

| 状态 | 判定条件 |
| --- | --- |
| 较少 | 50% 位置探头未被持续遮挡 |
| 约半 | 50% 位置持续遮挡 ≥ 5 秒，100% 位置未遮挡 |
| 全满 | 100% 位置持续遮挡 ≥ 5 秒 |

- **持续遮挡**用于区分“站在队列里”与“路过”：快速流动的人群只形成短脉冲，不触发分级。
- **滞回**：升级即时生效，降级需持续 15 秒未遮挡，避免状态抖动。
- **交叉校验**：与进出计数得到的在场人数比对，人数过低时不判为“全满”。

**设计取舍**：采集与联网分离为两块板。ESP32 的 Wi-Fi 重连或复位不会中断 STM32 的采集与写卡，保证实验数据连续；换站点时只需更换网关，采集固件无需改动。

**范围说明**

本期排队长度以**三级离散分级**（较少 / 约半 / 全满）表示，不提供连续人数或等待分钟数；连续长度估计与等待时间模型留作后续迭代。

**用户与受益者**

- 直接用户：等待服务的学生与教职工 —— 减少盲目等待
- 受益方：服务点管理方 —— 掌握需求分布，用于排班与引导

**核心交付**：可工作原型（采集 + 存储 + 无线上报）+ 网页仪表板（实时状态 / 历史曲线 / 告警）+ 对照人工计数的验证证据

## 2. 验收标准

| 编号 | 验收项 | 标准 | 验证方式 |
| --- | --- | --- | --- |
| A1 | 排队长度分级 | 三级（较少 / 约半 / 全满）判定与人工观测一致率 ≥ 80% | 同时段对照，重复 ≥ 5 次，三种状态均覆盖 |
| A2 | 拥挤状态判定 | 综合在场人数、进出流量与队列分级，对照人工观测准确率 ≥ 80% | 覆盖空闲 / 正常 / 高峰三类场景 |
| A3 | 端到端延迟 | 现场变化到网页更新 ≤ 5 秒 | 秒表与系统日志时间戳比对 |
| A4 | 稳定性 | 连续运行 ≥ 4 小时无崩溃、无丢数 | 长时运行记录与计数连续性检查 |
| A5 | 隐私合规 | 无可见光摄像头、无人脸或身份识别，仅保存聚合计数 | 方案与数据审查 |
| A6 | 集成原型 | 至少 2 类有意义的数据输入（进出流量、队列阈值），端到端可工作 | 现场演示 |
| A7 | 测试证据 | 单元 / 集成 / 系统测试对照需求，有记录 | 测试记录与导出的计数数据集 |
| A8 | 仪表板 | 实时状态 + 历史曲线 + 告警机制 | 现场演示（网页） |
| A9 | 跨国复制 | 说明 UL 与 LICHPU 部署的差异与可行性 | 报告章节 |

> 上述阈值需在需求关口前与教员确认后固化，并细化为可测试的需求条目。
