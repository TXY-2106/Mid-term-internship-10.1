# 面向校园服务窗口的双光束红外排队监测器

> UL–LICHPU 智慧校园生活实验室 · 中期实习 10.1 · 15 ECTS · 12 周实施周期
>
> 文档类型：技术方案 · 语言：中文（[English version](proposal.md)）

## 1. 引言

校园服务窗口——食堂档口、图书馆咨询台、打印点与咖啡档口——在高峰时段集中形成队列。使用者在加入队列前无法判断等待情况，服务点管理方也无法实时掌握需求分布，结果既造成本可避免的拥堵，也使排班难以对准真实需求。

基于摄像头的人群监测在技术上有效，但会采集可识别特征。对校园部署而言这不可接受；而"先匿名化再使用网络数据"的替代路线也有实质代价——已有研究表明，Wi-Fi 会话数据必须退化到小时粒度并叠加噪声才可用于共享 [4]。

本项目采用另一条路线。它不感知人长什么样、携带什么设备，只感知**人何时跨过一条边界**。两对红外光电束分别标记单列排队通道的队尾与队首。双向计数各方向的跨越事件，直接得到当前排队人数；到达率与服务率也可由同一批事件导出。本方案刻意收窄：一种明确定义的队列几何、一种传感原理、一个边缘节点。

## 3. 相关工作

**基于摄像头的人群分析**是既有主流方案，也是精度参照，但侵犯隐私且成本更高。**基于 LiDAR 的排队监测**通过点云聚类（一簇一人）完全避免成像 [2]，隐私友好且不受光照影响，但单个 360° LiDAR 就占据主要物料成本，且已发表工作为演示性质，未给出量化精度。

**红外阵列感知**已在队列场景得到验证：MLX90640 32×24 阵列搭配 STM32L476，在人与人间距小于 80 cm 时可检测每条队列最多 6 人、准确率 93% [3]。这确认了热感知在队列中可用，同时也记录了它的密度上限——真正的约束是分辨率而非成本。

**双向红外光束计数**与本项目最为接近。dos Santos 等 [1] 用 ESP32 与 **E18-D80NK** 构建计数器，配 RTC 与 microSD 记录，并在两个真实场景中验证：公交车门（**91.45%**）与**大学餐厅闸机（98.65%）**。其计数规则是——**仅当两个传感器在 300 ms 窗口内先后被触发才计为一次跨越**，方向由触发先后决定——直接解决了单束计数器长期存在的误触发与方向歧义问题。其误差分类也指出，**两人同时通过**是主要的残余误差来源。

**研究空白**：已发表的排队监测工作，或报告实验室条件下的传感性能，或报告闸口处的流量计数精度；尚无工作在可复制的物料成本下，同时报告**对照人工基线的排队长度误差**与**由利特尔法则导出的等待时间估计**。对单列排队通道而言，这一组合正是本项目的贡献。

## 4. 技术方案

### 4.1 系统总览

```
 入口闸（2 束） --EXTI--> 方向状态机 --> λ_in   (+)
 出口闸（2 束） --EXTI--> 方向状态机 --> λ_out  (-)
                                  │
                    STM32F103C8T6 边缘节点
                    ├── L(t)  = Σ入 − Σ出              占用数
                    ├── W     = mean(L) / mean(λ)      利特尔法则
                    └── L_mod = λ / (μ − λ)            M/M/1 互校
                                  │
            OLED 本地显示  +  MQTT（3 s）  →  网页仪表板
                                  │
                     microSD 事件日志（验证证据）
```

### 4.2 队列区与安装几何

监测区定义为单列排队通道：宽 60–90 cm，长至 6 m，队尾设入口、距服务台 0.5 m 处设出口。区域边界由两个闸口界定，**区域内部不做任何感知**。

每个闸口使用两枚 **E18-D80NK** 漫反射式红外传感器（检测距离 3–80 cm 可调），沿行进方向间距 10 cm、安装高度约 100 cm。10 cm 间距配合 1.2–1.4 m/s 的步行速度，两束被遮挡的时间差约 70–85 ms，远高于 20 ms 消抖，且落在 300 ms 符合窗口之内。

### 4.3 计数与方向判别

依照 [1]，**仅当同一闸口的两束都在 300 ms 内被触发**才计为一次跨越；单束触发视为误触发而丢弃。方向由触发先后决定：A 先 B 后为一个方向，B 先 A 后为反向。20 ms 消抖抑制触点抖动，2 s 阻塞超时用于丢弃"人停留在光束内"的事件。

每个闸口独立运行状态机，入口与出口互不干扰：

```
IDLE --A 或 B 被遮挡--> HALF_HIT（记时刻）
HALF_HIT --300 ms 内第二束被遮挡--> 判定方向 → 发出事件 → IDLE
HALF_HIT --超时，或遮挡超过 2 s--> 丢弃 → IDLE
```

### 4.4 占用数核算与漂移校正

排队长度由流量守恒得到：

```
L(t) = Σ入 − Σ出 ，  并夹紧 L ≥ 0
```

占用数核算有一个结构性弱点：**误差会累积**。一次漏计永远无法被自动找回，因此系统性偏差会使 L 无界漂移。本方案采用两级缓解：其一，双束符合规则消除了最大一类虚假事件；其二，执行**空区归零**——当两闸口均持续静默、且最近一次事件为"出"时，判定队列为空并将 L 归零。归零动作本身写入日志，使校正过程可审计。

### 4.5 利特尔法则与等待时间

排队长度与到达率可由系统独立测得，等待时间即由利特尔法则得到：

```
W = mean(L，窗口) / mean(λ，窗口)          窗口 = 5 分钟
```

必须采用时间平均形式，因为利特尔法则描述的是长期平均关系；用瞬时 L 除以平均 λ 会产生偏差。当 λ 低于下限阈值时，状态上报为**空闲**、W 报为不可用，而不是给出一个无界值。

由于出口闸测得服务率 μ，M/M/1 模型可给出第二个、完全不依赖占用数的预测：

```
L_mod = λ / (μ − λ) ,     W_mod = 1 / (μ − λ)
```

两者之差 `|L − L_mod|` 作为一致性指标上报，并用于标记异常情形（例如有人未经过出口闸即离开队列）。

排队状态由 L 与 W 的双阈值判定，因此上报的状态同时反映"有多少人在等"与"已经等了多久"。

### 4.6 边缘软件

固件为裸机时间片架构，分驱动层、服务层、应用层与 HAL 四层，中断与任务之间以事件环形缓冲解耦，**中断上下文内不执行任何算法**。

| 模块 | 职责 |
| --- | --- |
| `e18` | 4 路 EXTI、消抖、方向状态机、事件队列 |
| `tracker` | 占用数、λ、μ、W、M/M/1 互校、状态判定 |
| `ds3231` / `sdlog` | 时间戳与可审计的事件日志 |
| `oled` / `esp_at` | 本地显示与 MQTT 发布 |
| `main` | 1 ms 时基；10 ms 状态机；1 s 统计与显示；3 s 发布；5 s 写日志 |

本地显示在 1 s 内更新、MQTT 每 3 s 发布，相对 5 s 端到端延迟指标留有裕量。

### 4.7 隐私设计

系统**不含任何成像器件**。它测量的是两束漫反射红外光是否被遮挡，由此只导出一个计数与一个方向。不采集任何外观、步态、人脸、设备地址或个人标识。仅聚合计数与速率经 MQTT 离开节点；原始跨越事件留在本地 microSD 卡作为验证证据，不上传。

## 5. 评估计划

| 编号 | 验证方式 |
| --- | --- |
| A1 | 在 0–20 人各密度档同步人工计数，重复 ≥ 5 次；报告平均绝对误差与"误差-密度"曲线 |
| A2 | 在空闲、正常、高峰三类场景下将判定状态与人工观测比对，报告准确率 |
| A3 | 以秒表观测与系统日志时间戳比对，报告延迟分布 |
| A4 | 连续运行 4 h 并保留 SD 事件日志，统计故障 |
| A5 | 方案与数据审查：确认无成像器件、无生物特征处理、仅传输聚合值 |
| A6 | 两闸口同时工作的端到端演示 |
| A7 | 用注入的合成事件对方向状态机与占用数追踪做单元测试；集成与系统测试对照 O1–O6，以 SD 事件日志与人工计数表为证据 |
| A8 | 现场演示实时状态、历史曲线与告警 |
| A9 | 文档化 UL 与 LICHPU 的部署对比，含成本、安装与基础设施依赖 |

评估协议参照 [1]：该工作以反复的"人工计数与自动计数同步进行"方式验证了同类计数器，并同时报告总体精度与误差类型分解。

## 6. 风险与缓解

| 风险 | 影响 | 缓解措施 |
| --- | --- | --- |
| 两人同时通过 | 漏计，进而引发漂移 | 双束符合规则；单列通道几何；给出误差-密度特性。该情形是 [1] 中主要误差来源 |
| 占用数累积漂移 | 排队长度误差无界 | 空区归零；归零记录可审计；M/M/1 一致性互校 |
| 有人停留在光束内 | 虚假或阻塞事件 | 2 s 阻塞超时 |
| 点位无单列排队通道 | 方法不成立 | 在第 1–2 周、设计关口之前确认服务点与队列几何 |
| **[1] 的精度是流量精度，非排队人数精度** | 预期被高估 | 明确说明占用数误差会累积；以人工计数实测，而非直接套用 91.45% 这一数字 |
| 器件一致性（E18-D80NK 检测距离存在离散） | 检测区不一致 | 安装时以实物量具逐只标定电位器；把该流程写入文档以支持复制 |

## 7. 进度计划

项目遵循仓库 README 中定义的 12 周时间线与各关口。软硬件里程碑对应如下：第 4 周完成单闸口的台式验证；第 5 周两闸口联通并接通占用数追踪；第 6 周完成含仪表板的集成原型；第 7 周标定阈值、消抖与窗口参数；第 8 周开展验证活动；第 9–10 周完成分析与设计冻结；第 11–12 周完成报告与演示。

**交付物**：集成的可工作原型；实时本地显示；带历史曲线的网页仪表板；源码仓库与文档；对照人工基线的验证证据。
