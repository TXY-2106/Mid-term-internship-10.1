# 面向校园服务窗口的四光束红外排队监测器

> UL–LICHPU 智慧校园生活实验室 · 中期实习 10.1 · 15 ECTS · 12 周实施周期
>
> 文档类型：技术方案 · 语言：中文（[English version](proposal.en.md)）

## 1. 引言

校园服务窗口——食堂档口、图书馆咨询台、打印点与咖啡档口——在高峰时段集中形成队列。使用者在加入队列前无法判断等待情况，服务点管理方也无法实时掌握需求分布，结果既造成本可避免的拥堵，也使排班难以对准真实需求。

基于摄像头的人群监测在技术上有效，但会采集可识别特征。对校园部署而言这不可接受；而"先匿名化再使用网络数据"的替代路线也有实质代价——已有研究表明，Wi-Fi 会话数据必须退化到小时粒度并叠加噪声才可用于共享 [4]。

本项目采用另一条路线。它不感知人长什么样、携带什么设备，只感知**人何时跨过一条边界**。四路红外光电束分工明确：入口处两束比较触发先后以判定进 / 出，队列方向上两束分别置于约 50% 与 100% 位置，作为排队长度阈值。本方案刻意收窄：一种明确定义的队列几何、一种传感原理、两块低成本开发板。

## 2. 目标与范围

| 编号 | 目标 | 指标 | 对应验收 |
| --- | --- | --- | --- |
| O1 | 排队长度分级 | 三级（较少 / 约半 / 全满）判定与人工观测一致率 ≥ 80% | A1 |
| O2 | 拥挤状态判定 | 综合在场人数与队列分级，对照人工观测准确率 ≥ 80% | A2 |
| O3 | 端到端延迟 | 现场变化到网页更新 ≤ 5 s（上报 250 ms、网页轮询 400 ms） | A3 |
| O4 | 运行稳定性 | 连续运行 ≥ 3 h 无崩溃、无丢数 | A4 |
| O5 | 隐私保护 | 不含任何成像器件；仅输出聚合计数 | A5 |
| O6 | 历史人数预测 | 按近 7 天同一 15 分钟时段的平均在场人数给出预测值，并标注参与天数 | A8 |
| O7 | 成本与可复制性 | 每服务点物料成本低于 ¥150；说明 UL 与 LICHPU 的部署差异 | A9 |

**范围内**：单列排队通道的匿名进出计数、在场人数、三级排队分级、基于历史的同时段人数预测；本地 SD 卡长期记录；带实时状态、历史曲线与告警的网页仪表板；对照人工基线的验证。

**范围外**：连续人数估计与等待分钟数（利特尔法则一类的时间模型留作后续迭代）；个人身份识别；人脸或步态识别；考勤或执法用途；对校方排班的自动化决策；无明确排队通道的开阔场所感知。

## 3. 相关工作

**基于摄像头的人群分析**是既有主流方案，也是精度参照，但侵犯隐私且成本更高。**基于 LiDAR 的排队监测**通过点云聚类（一簇一人）完全避免成像 [2]，隐私友好且不受光照影响，但单个 360° LiDAR 就占据主要物料成本，且已发表工作为演示性质，未给出量化精度。

**红外阵列感知**已在队列场景得到验证：MLX90640 32×24 阵列搭配 STM32L476，在人与人间距小于 80 cm 时可检测每条队列最多 6 人、准确率 93% [3]。这确认了热感知在队列中可用，同时也记录了它的密度上限——真正的约束是分辨率而非成本。

**双向红外光束计数**与本项目最为接近。dos Santos 等 [1] 用 ESP32 与 **E18-D80NK** 构建计数器，配 RTC 与 microSD 记录，并在两个真实场景中验证：公交车门（**91.45%**）与**大学餐厅闸机（98.65%）**。其计数规则是——**仅当两个传感器在 300 ms 窗口内先后被触发才计为一次跨越**，方向由触发先后决定——直接解决了单束计数器长期存在的误触发与方向歧义问题。其误差分类也指出，**两人同时通过**是主要的残余误差来源。

**研究空白**：已发表的排队监测工作，或报告实验室条件下的传感性能，或报告闸口处的流量计数精度；尚无工作在可复制的物料成本下，同时报告**对照人工基线的排队分级一致性**与**基于历史数据的同段人数预测**。对单列排队通道而言，这一组合正是本项目的贡献。

## 4. 技术方案

### 4.1 系统总览

```
 入口 A/B（PB12/PB13）   队列 50%/100%（PB14/PB15）
        │ 1 kHz 采样，5 ms 去抖
        ▼
 STM32F103C8T6 边缘节点
   ├── 方向状态机：300 ms 双束符合 → 进 / 出 / 在场人数
   ├── 分级状态机：持续遮挡 5 s 升级、持续通光 15 s 降级，并用在场人数交叉校验
   ├── 历史表：7 天 × 96 段（15 min），仅统计已结束的时段
   ├── I²C1 → DS3231 时间基准
   └── SPI1 → SD 卡：events.csv / status.csv / HYYMMDD.CSV
        │ UART 115200，每 250 ms 一帧 $QSM,…*CRC8
        ▼
 ESP32 自建热点「QSM-Monitor」192.168.4.1
        │ Wi-Fi
        ▼
 手机 / 电脑网页：实时状态 · 分级趋势 · 预测人数 · 四路探头状态 · 复位按钮
        ▲
        └── 下行命令 $QSR,<cmd>*CRC8（清计数 / 清历史 / 全部复位）
```

采集与联网分离为两块板：ESP32 的 Wi-Fi 重连或复位不会中断 STM32 的采样与写卡；换站点时只需更换网关，采集固件无需改动。

### 4.2 队列区与安装几何

监测区定义为单列排队通道：宽 60–90 cm，长至 6 m。入口处两枚 **E18-D80NK** 沿行进方向间距 10 cm、安装高度约 100 cm，用于判定进出方向；队列方向上另两枚分别置于通道约 50% 与 100%（队尾）位置，安装高度同为约 100 cm，用于分级。探头均为漫反射式，检测距离 3–80 cm 可调，安装时逐只标定电位器。

10 cm 间距配合 1.2–1.4 m/s 的步行速度，两束被遮挡的时间差约 70–85 ms，远高于 5 ms 去抖，且落在 300 ms 符合窗口之内。

### 4.3 计数与方向判别

依照 [1]，**仅当入口两束都在 300 ms 内被触发**才计为一次跨越；单束触发视为误触发而丢弃。方向由触发先后决定：A 先 B 后为入场，B 先 A 后为离场。系统以 1 kHz 定时采样并做 5 点移位去抖（等效 5 ms），另设 2 s 阻塞超时，用于丢弃"人停留在光束之间"的手势。

```
IDLE --A 或 B 被遮挡--> HALF_HIT（记时刻）
HALF_HIT --300 ms 内第二束被遮挡--> 判定方向 → 发出事件 → IDLE
HALF_HIT --超时，或遮挡超过 2 s--> 丢弃 → IDLE
```

在场人数由 `Σ入 − Σ出` 得到并夹紧到 ≥ 0；计数误差会累积，因此分级判定始终与在场人数交叉校验：人数过低时不判为"全满"。本期不做自动归零，漂移以人工基线校准与日志复核处理。

### 4.4 排队长度分级

| 状态 | 判定条件 |
| --- | --- |
| 较少 | 50% 位置探头未被持续遮挡 |
| 约半 | 50% 位置持续遮挡 ≥ 5 s，且 100% 位置未遮挡 |
| 全满 | 100% 位置持续遮挡 ≥ 5 s |

- **持续遮挡**用于区分"站在队列里"与"路过"：快速流动的人群只形成短脉冲，不触发分级。
- **滞回**：升级即时生效，降级需持续通光 15 s，避免状态抖动。
- **交叉校验**：与进出计数得到的在场人数比对，人数过低时不判为"全满"，冲突时置位上报标志。

### 4.5 历史人数预测

排队人数有明显的时间规律（午高峰、课间），因此用"同一时段的历史平均"作为预测：

```
pred(t) = mean( occ(d, t) )，d ∈ 最近 7 天中已完成的日子
pred_n  = 参与平均的天数（0 表示历史不足）
```

- 时间轴切成 **15 分钟 × 96 段**，每段每人一条记录；STM32 用 7×96 的 `uint8` 表驻留（共 672 B），不开大缓冲。
- **今天不参与计算**：当天尚未走完，纳入会系统性偏低；因此至少需要一个完整的历史日才会有预测值。
- 分钟级采样写入 SD 卡（`HH:MM,occ`），上电时回读最近 8 天重建内存表，掉电重启后预测立即可用。
- 预测值与参与天数随 4 Hz 上报帧下发，网页显示"预测排队人数 / 参考天数"；历史不足时显示"—"而不是 0。

预测依赖真实时钟（DS3231）。若时钟不可用，系统无法判断"同一时段"，此时预测值保持为不可用，并在网页上明确显示，而不是给一个看似有效的数。

### 4.6 时间基准与数据存储

- **DS3231**（I²C1，地址 0x68，PB6/PB7）提供离线时间戳；固件对每次 I²C 等待都设超时，连续失败会自动做 9 个时钟的总线恢复，并对"开机时未识别到"的情形每 10 s 重试一次。
- **SD 卡**（SPI1，CS=PA4）以 FatFs R0.16 挂载，写入三类文件：

| 文件 | 内容 | 频率 |
| --- | --- | --- |
| `events.csv` | `datetime,uptime_ms,beam,level` | 每个边沿 |
| `status.csv` | `datetime,uptime_ms,in,out,occ,q50_ms,q100_ms,grade,flags` | 1 Hz |
| `HYYMMDD.CSV` | `HH:MM,occ`，每天一个文件 | 每分钟 |

- 采用 8.3 短名，卡需 FAT16/FAT32、≤ 32 GB；每 10 s 执行一次 `f_sync`，掉电最多丢 10 s。
- 文件系统时间戳固定为 2020-01-01（`FF_FS_NORTC`），不用作时间依据；真实时间以 `datetime` 列为准。

### 4.7 边缘软件与通信

固件为裸机时间片架构，`core/` 全部为无硬件依赖的纯 C（可在 PC 上跑单元测试），`stm32/` 与 `esp32/` 各自实现硬件与联网。

| 模块 | 职责 |
| --- | --- |
| `gate_counter` | 双束方向状态机、进出计数、在场人数 |
| `queue_grade` | 50%/100% 阈值分级、滞回、人数交叉校验 |
| `qsm_history` | 15 分钟槽位、日期换算、预测平均、文件行列格式化 |
| `hist_store` / `data_logger` / `bsp_sd_disk` | FatFs、SD 驱动、三类日志落盘与回读 |
| `protocol` | 上行帧编解码、CRC-8、下行命令帧 |
| `bsp_e18` / `bsp_uart` / `bsp_ds3231` | 1 kHz 采样去抖、UART 收发、RTC |

任务节拍：

| 周期 | 内容 |
| --- | --- |
| 1 kHz（SysTick） | 四路探头采样 + 去抖 |
| 10 ms | 边沿出队、状态机推进、分级计时 |
| 250 ms | 组上行帧发往 ESP32（4 Hz） |
| 1 s | 写 `status.csv`、刷调试行 |
| 10 s | `f_sync` 落盘 |
| 60 s | 历史表记录一行 |

上行帧格式（`*` 后为两位十六进制 CRC-8）：

```
$QSM,<seq>,<ms>,<datetime>,<in>,<out>,<occ>,<q50_ms>,<q100_ms>,<grade>,<flags>,<pred>,<pred_n>,<beams>*<CRC8>
```

后三个字段为后续新增，解析端按索引读取、缺省补 0，因此新老固件互通。ESP32 以 **AP 模式**自建热点并在固定地址 `192.168.4.1` 托管仪表板，现场不需要任何既有网络；网页每 400 ms 轮询 `/api/state`，超过 2.5 s 无新帧即以橙色条提示断流。

### 4.8 隐私设计

系统**不含任何成像器件**。它测量的是红外光束是否被遮挡，由此只导出一个计数、一个方向与两个阈值状态。不采集任何外观、步态、人脸、设备地址或个人标识。离开节点的只有聚合后的计数与分级，原始跨越事件只写本地 SD 卡作为验证证据，不上传云端。

## 5. 评估计划

| 编号 | 验证方式 |
| --- | --- |
| A1 | 在三种分级状态下同步人工观测，重复 ≥ 5 次，覆盖全部三种状态；报告一致率 |
| A2 | 在空闲 / 正常 / 高峰三类场景下综合在场人数与分级判定拥挤状态，对照人工观测，报告准确率 |
| A3 | 以秒表与系统日志时间戳比对，报告"现场变化→网页更新"的延迟分布 |
| A4 | 连续运行 3 h 并保留 SD 日志，统计崩溃与丢数（以 `seq` 连续性检查） |
| A5 | 方案与数据审查：确认无成像器件、无生物特征处理、仅传输聚合值 |
| A6 | 四路探头同时工作的端到端演示：进出计数 + 分级阈值 |
| A7 | 用注入的合成事件对方向状态机、分级状态机、历史预测与帧编解码做单元测试；集成与系统测试对照 O1–O7，以 SD 日志与人工计数表为证据 |
| A8 | 现场演示实时状态、分级趋势、预测人数与告警 |
| A9 | 文档化 UL 与 LICHPU 的部署对比，含成本、安装与基础设施依赖 |

评估协议参照 [1]：该工作以反复的"人工计数与自动计数同步进行"方式验证了同类计数器，并同时报告总体精度与误差类型分解。

## 6. 风险与缓解

| 风险 | 影响 | 缓解措施 |
| --- | --- | --- |
| 两人同时通过 | 漏计，进而引发在场人数漂移 | 双束符合规则；单列通道几何；与分级交叉校验。该情形是 [1] 中主要误差来源 |
| 计数漂移 | 在场人数与分级逐渐失真 | 分级以探头为主证据、人数只作校验；以人工基线复核并写入日志。本期不做自动归零 |
| 时钟缺失或掉线 | 历史无法按"同一时段"归档，预测不可用 | I²C 全程超时 + 总线恢复；开机未识别时每 10 s 重试；网页显式显示"历史不足"而非 0 |
| 历史积累不足 | 首日无预测值 | 明确预期：需至少一个完整历史日；预测值与参与天数一并显示 |
| 探头串扰 / 安装偏差 | 误触发或漏触发 | 5 ms 去抖；10 cm 间距；安装时逐只标定检测距离 |
| 有人停留在光束内 | 虚假或阻塞事件 | 2 s 阻塞超时 |
| 点位无单列排队通道 | 方法不成立 | 在设计关口之前确认服务点与队列几何 |
| **[1] 的精度是流量精度，非排队人数精度** | 预期被高估 | 以人工基线实测分级一致率，而非直接套用 91.45% |

## 7. 进度计划

项目遵循仓库 README 中定义的 12 周时间线与各关口。硬件与固件里程碑：第 1–4 周确认方案与队列几何、完成单闸口台式验证；第 5–6 周四路探头联通、计数与分级状态机成形；第 7 周历史预测与 SD 落盘；第 8 周网页仪表板与实时性；第 9–10 周现场验证与设计冻结；第 11–12 周完成报告与演示。

**交付物**：集成的可工作原型；实时网页仪表板（含预测与复位）；源码仓库与文档；对照人工基线的验证证据。
