# ESP32 网关（Arduino IDE）

功能：接收 STM32 的 `$QSM` 帧 → 连 Wi-Fi → 托管网页仪表板。**不做任何计数判定**。

## 环境准备

1. Arduino IDE → 文件 → 首选项 → 附加开发板管理器网址，填（国内镜像，走 `dl.espressif.cn`）：

   ```
   https://arduino.me/packages/esp32.json
   ```

2. 工具 → 开发板 → 开发板管理器 → 搜索 `esp32` → 安装 **esp32 by Espressif Systems `3.2.1-cn`**
3. 开发板选 **ESP32 Dev Module**，端口选 CH340 对应的 COM 口

> 镜像最高为 3.2.1，比官方 3.3.12 旧一个小版本，本项目功能不受影响。注意 ESP32 core **3.x 与 2.x 的部分 API 有差异**，查文档时看清版本。

## 打开与修改

1. 用 Arduino IDE 打开 `qsm_monitor/qsm_monitor.ino`（草图中所有 `.h/.cpp` 会一起编译）
2. 在 **`config.h`** 里选联网方式（**只改这一个数**）：

   ```c
   #define WIFI_MODE       1     /* 1=自建热点  2=连现场Wi-Fi  3=两者同时 */
   ```

   | 模式 | 地址 | 什么时候用 |
   |---|---|---|
   | `1` AP（**默认**） | `http://192.168.4.1` **永远不变** | **演示**：不依赖现场网络，插电就能用 |
   | `2` STA | 路由器分配的 IP，看串口打印 | 平时开发、要上网 |
   | `3` APSTA | 两者都有，热点兜底 | 想连现场网又怕连不上 |

   选 `2` 或 `3` 才需要填 `WIFI_SSID` / `WIFI_PASSWORD`；选 `1` 不用填任何 Wi-Fi。

   > **演示建议用模式 `1`**：ESP32 自己开热点 `QSM-Monitor`（密码 `qsm12345`），
   > 手机或笔记本连上它，浏览器打开 `http://192.168.4.1` 即可。
   > 这样你在**任何一台电脑上烧录一次**，之后插电就能演示，不用串口、不用找 IP、不依赖场地 Wi-Fi。
   > 手机若提示"此 WLAN 无法访问互联网"，选**保持连接**即可。

3. 上传

## 接线

依据仓库 [`hardware/硬件接线说明.md`](../../../hardware/硬件接线说明.md)：

| ESP32 | STM32 | 说明 |
|---|---|---|
| GPIO16 (U2RXD) | **PA2** (USART2_TX) | STM32 → ESP32 |
| GPIO17 (U2TXD) | **PA3** (USART2_RX) | ESP32 → STM32 |
| GND | GND | **必须共地** |
| Type-C | — | 充电宝供电（USB-A 转 Type-C） |
| VIN | 5V | 由 ESP32 的 VIN 分出 5V 给 STM32 / E18×4 / SD 卡座 |

> **不要**把 ESP32 的 3V3 与 STM32 的 3V3 并联；**不要**给 STM32 插 Type-C。
> ESP32 发射瞬时电流可达 300 mA，务必由充电宝独立供电并在模块旁加 470 µF 电容，否则会复位。

## 使用

上传后打开串口监视器（115200），会看到一张启动横幅，例如模式 `1` 时：

```
========================================
  排队状态监测器 已启动
  热点: QSM-Monitor   密码: qsm12345
  打开: http://192.168.4.1
  (手机提示"无互联网"时选"保持连接")
========================================
[QSM] http server started on port 80
```

模式 `2` / `3` 连上现场 Wi-Fi 时还会多打印一行 `[WiFi] connected, open http://192.168.x.x`。

**演示流程（模式 1，全程不需要电脑）**：

1. 充电宝给 ESP32 供电（Type-C），ESP32 的 VIN 分出 5V 给 STM32 / E18 / SD 卡
2. 手机或笔记本连 Wi-Fi `QSM-Monitor`，密码 `qsm12345`
3. 浏览器打开 `http://192.168.4.1`

浏览器即可看到仪表板：三级状态色块、在场人数、累计进出、两路探头遮挡时长、**预测排队人数（近 7 天同时段平均）**、**四路探头实时状态**、最近 2 分钟趋势条、拥挤告警。

页面**中英双语**：每个标签中文为主行、英文为下方灰色小字（如 `在场人数 / People now`、`预测排队人数 / Predicted queue length`），
三级状态也双语（`较少 / Few`、`约半 / About half`、`全满 / Full`），标题、告警、底部状态行同样双语。
不需要切换按钮——两种语言同时显示，投屏和给外方看都不用改设置。

预测那一块是单独一张浅蓝卡片，数字用 34 px 大字显示，右侧一栏写"参考天数（近 7 天同时段）"，
例如 `9` + `4 天 / 4 day(s)` 表示过去 7 天里有 4 天在该时段有数据、平均 9 人。

> 预测值由 STM32 计算后放在帧尾发过来（`pred` / `pred_n`），本机只负责显示；
> `predn=0` 表示历史不足（刚上电、或没接 DS3231），此时数字位显示 `—`、说明位显示"历史不足 / not enough history"。

"四路探头实时状态"卡片显示 **入口 A / 入口 B / 队列 50% / 队列 100%** 四支探头：
遮挡时圆点亮橙色、文字"遮挡"，通光时"通光"。它由帧尾的 `beams` 位图驱动，
用来在**不接调试串口**的情况下逐支确认探头有没有响应（接线、供电、检测距离）。

| 现象 | 说明 |
|---|---|
| 某一位始终"通光" | 该支探头没触发：查 5V 供电（E18 必须 5V）、检测距离电位器、棕/蓝线序 |
| 某一位始终"遮挡" | 该支探头常闭型（NC）或黑线被下拉，`APP_E18_ACTIVE_LOW` 需取反 |
| 四位全对、但人数不涨 | 停在"单探头模式"或两支入口探头间距过大（超出 300 ms 符合窗口） |

"外设状态（现场排查用）"卡片显示四项，全部由帧里的 `flags` 解析：

| 项 | 绿（正常） | 红（未就绪） | flags |
|---|---|---|---|
| 时序单元 DS3231 | RTC 正常，时间戳可信 | 没认到模块：时间戳为 `-`，历史与预测都不会累积 | bit0 `RTC_OK` |
| SD 卡 | 卡已挂载，正在写日志 | 未挂载/写失败：`events.csv`、`status.csv`、`HYYMMDD.CSV` 都不会更新 | bit1 `SD_OK` |
| 交叉校验 | 分级与在场人数一致 | 两者矛盾（多半是探头误触发或装反） | bit2 `CROSS_CONFLICT` |
| 历史样本 | 显示参与平均的天数 | `0 天 / no sample` | 由 `predn` 推断 |

时序单元那一格下面还有一行 I2C 扫描提示（由帧尾 `i2c` 字段驱动）：

| 提示 | 含义 |
|---|---|
| 绿色"总线正常" | 0x68 应答且时间戳正常 |
| 黄色"0x68 有应答，但读取失败" | 模块在线、地址对，问题在寄存器读写或接触 |
| 红色"只发现 0x57" | 总线被 EEPROM/其他器件占着，DS3231 未响应 |
| 红色"发现其他器件" | 有器件但地址不是 0x68/0x57 |
| 红色"总线上没有任何应答" | 断线、没供电或没有上拉 |

页脚还打印了 `flags 0x??`，方便直接对照上表；排障时先看这一行，比翻 CSV 快。

### 一帧都没收到时怎么判断

顶部的橙色断流条会直接给出结论，背后是 `serial_link` 统计的**原始接收字节数 `rx`**：

| 页面提示 | 说明 | 下一步 |
|---|---|---|
| 还没收到任何字节 | `rx = 0`，USART2 上一个字节都没进来 | STM32 是否上电；PA2(TX)→GPIO16(RX2)、PA3(RX)→GPIO17(TX2) 是否**交叉**；两块板是否**共地** |
| 收到 N 字节但没有完整帧 | 有电信号但解析失败（`bad` 接近 `rx`） | 波特率是否 115200；TX 是否只接了半根（接触不良）；线太长/共地不良 |
| 数据已 X 秒未更新 | 曾收到过好帧，现在断了 | 看 `good/bad/rx` 是否还在涨，判断是 STM32 停了还是线松了 |

页脚 meta 行会同时打印 `good / bad / rx B / age / flags`，接线时不用开串口助手。

> 若装了 Bonjour，也可以访问 `http://qsm.local`；**不确定就还是用 IP，IP 永远可用**。

## 现场常见问题

| 现象 | 原因 / 处理 |
|---|---|
| 手机连上热点却打不开 `192.168.4.1` | 手机把该热点当成"无互联网 WLAN"自动切回流量，关掉移动数据或选"保持连接" |
| 换了场地，`192.168.4.1` 打不开 | 你烧的是模式 `2`（STA），IP 变了；改回模式 `1` 重烧 |
| 网页一直显示"等待数据" | STM32 没在发帧：查 PA2→GPIO16 接线、共地、STM32 是否已烧录 |
| 热点开了但搜不到 | 密码少于 8 位会开热点失败，`AP_PASSWORD` 至少 8 个字符 |

## HTTP 接口

| 路径 | 说明 |
|---|---|
| `/` | 仪表板网页（内嵌，无外部依赖，断网可用） |
| `/api/state` | 最新状态 JSON，含链路统计与告警阈值 |
| `/api/reset?cmd=1|2|3` | 下发复位命令给 STM32（1=清零计数，2=清空历史，3=两者都做） |
| `/api/settime?iso=YYYY-MM-DDThh:mm:ss` | 把浏览器本地时间写进 STM32 的 DS3231（19 字符，越界由 STM32 拒绝） |

`/api/state` 示例：

```json
{"valid":true,"seq":1024,"ms":3735000,"datetime":"2026-10-28T12:31:04",
 "in":37,"out":29,"occ":8,"q50":6100,"q100":0,"grade":2,"flags":19,
 "pred":9,"predn":4,"beams":5,"i2c":1,
 "good":1024,"bad":0,"age":450,"alert_grade":2,"alert_occ":8}
```

`pred` 是预测排队人数，`predn` 是参与平均的天数（0=历史不足）。它们来自帧尾两个新字段，
老固件不含这两个字段时按 0 处理，页面显示"历史不足"。

`beams` 是四路探头电平位图：bit0 入口A、bit1 入口B、bit2 队列50%、bit3 队列100%，1=遮挡。

`i2c` 是开机 I2C 扫描结果：bit0=0x68(DS3231) 有应答、bit1=0x57 有应答、bit2=其他器件有应答，0=总线上什么都没找到。
示例 `5` = `0b0101` = 入口A 与 队列50% 同时被遮挡。老固件不含该字段时按 0（全部通光）处理。

`good` / `bad` / `age` 三个字段是现场排障用的：`bad` 持续增长说明串口干扰或两端协议不一致，`age` 过大说明 STM32 掉线或没在发。

## 文件说明

| 文件 | 职责 |
|---|---|
| `qsm_monitor.ino` | 入口：初始化、主循环、Wi-Fi 后台重连 |
| `config.h` | Wi-Fi、串口引脚、历史长度、告警阈值 |
| `serial_link.cpp/.h` | 帧解析 + CRC8 校验（须与 `firmware/core/protocol.c` 一致） |
| `web_server.cpp/.h` | HTTP 路由与 JSON 序列化 |
| `web_page.h` | 内嵌 HTML/CSS/JS（单页，400 ms 轮询，含复位按钮与断流提示） |

## 注意

- **CRC 算法两端必须一致**：改 `firmware/core/protocol.c` 的 `qsm_crc8` 时，必须同步改 `serial_link.cpp` 的同名函数。
- 网页用 **400 ms** 轮询而非 WebSocket/SSE，是为了让整页逻辑足够短、便于现场排障；
  STM32 侧每 250 ms 发一帧，页面基本"抬手就变"，A3 要求 ≤5 s 余量很大。
- 断流超过 2.5 s，页面顶部会出现橙色"数据已 N 秒未更新"提示；`age` 字段同时显示在页脚。
- `config.h` 里的 `HISTORY_SIZE` 目前未用于服务端历史（趋势条在前端生成）；若要在服务端存 1 小时历史，需要再加环形缓冲与 `/api/history` 接口。


## 网页复位按钮

页面底部有三个按钮，点击即向 STM32 下发一行命令帧（`serial_link.cpp` 的 `link_send_cmd()`）：

| 按钮 | 帧 | STM32 动作 |
|---|---|---|
| 清零计数 | `$QSR,1*69` | 进/出人数、在场人数、分级归零 |
| 清空历史 | `$QSR,2*60` | RAM 历史表清零 + 删除 SD 卡最近 8 天的 `H*.CSV` |
| 全部复位 | `$QSR,3*67` | 上面两件都做 |

页面底部还有"时间校准（时序单元）"卡片：显示 STM32 上报的当前时间（`datetime`），
点"校准到本机时间"即用浏览器 `new Date()` 生成 `YYYY-MM-DDThh:mm:ss`，
打 `/api/settime?iso=...`，ESP32 组帧 `$QST,<iso>*<CRC8>` 走 USART2 下发。
装不装纽扣电池都一样：**首次使用必须校一次**（电池只负责掉电后继续走时）。
DS3231 掉电或纽扣电池没电时读回 2000-01-01，校时一次即可；成功时该卡片里的
时间会在 1 秒内开始跳动。

命令走 USART2 下行（GPIO17 → STM32 PA3），CRC8 与上行帧同一算法；STM32 侧在中断里收、
主循环里解析，**因此不用再按 STM32 的复位键**。发完命令后 1 s 内 `/api/state` 就会反映新值。

`/api/reset` 也支持直接 GET 调用，例如浏览器打开 `http://192.168.4.1/api/reset?cmd=1`。
