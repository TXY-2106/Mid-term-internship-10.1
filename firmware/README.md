# firmware —— 排队状态监测器固件

按仓库 `README.md` 已确认的方案实现：**4 路 E18-D80NK 红外光电开关 + STM32F103C8T6 边缘采集 + ESP32 联网展示**，队列长度以**三级离散分级**（较少 / 约半 / 全满）表示，并按"过去 7 天同时段平均"给出排队人数预测。

> **范围**：本期不做连续人数与等待分钟数。`docs/proposal.md` 中的连续长度估计与利特尔法则等待时间模型，作为**后续迭代**（见文末「迭代路径」）。

## 目录结构

```
firmware/
├── core/                纯逻辑，无硬件依赖，可在 PC 上编译与单元测试
│   ├── qsm_types.h        共用类型、分级枚举、默认参数
│   ├── gate_counter.c/.h  双束方向判别 + 在场人数
│   ├── queue_grade.c/.h   持续遮挡计时 + 三级判定 + 滞回 + 交叉校验
│   ├── qsm_history.c/.h   历史表（7 天 × 96 段）记录/预测 + 日期与文件行格式换算
│   └── protocol.c/.h      串口帧编解码 + CRC8
├── stm32/               目标固件（Keil MDK5 + 标准外设库）
│   ├── App/               参数集中、主流程、CSV 日志、历史落盘（hist_store）
│   ├── BSP/               采样去抖、RTC、SD 卡（含 FatFs 磁盘 I/O）、串口
│   └── Middlewares/FatFs/ FatFs R0.16 + 自写 ffconf.h / diskio.c
├── esp32/qsm_monitor/   网关（Arduino IDE 草图工程）
└── tests/               core 的单元测试（gcc + make）
```

**为什么要单独分出 `core/`**：这部分才是真正的判定逻辑。把它与 HAL 解耦之后，可以脱离硬件在 PC 上跑测试——这正是验收标准 **A7「测试证据」** 最直接的来源，也避免"只能在板子上试出来"的调试困境。

## 数据流

```
E18 进出 ×2 ─┐
             ├─► STM32 ──SPI──► SD 卡（status.csv / events.csv / HYYMMDD.CSV）
E18 队列 ×2 ─┘      │
                    ├──I²C──► DS3231（离线时间戳）
                    └──UART──► ESP32 ──Wi-Fi──► 网页仪表板
```

两块板职责严格分离：**ESP32 掉线或重启，不影响 STM32 的采集与落盘**。

## 串口协议

单行 ASCII，115200 8N1，便于用任意串口助手肉眼调试：

```
$QSM,<seq>,<ms>,<datetime>,<in>,<out>,<occ>,<q50_ms>,<q100_ms>,<grade>,<flags>,<pred>,<pred_n>,<beams>*<CRC8>\n
```

真实样例（由 `tests/` 编译出的编码器生成）：

```
$QSM,1024,3735000,2026-10-28T12:31:04,37,29,8,6100,0,2,3,9,4,5*96
```

| 字段 | 含义 |
|---|---|
| `seq` | 帧序号，掉帧可发现 |
| `ms` | STM32 开机毫秒 |
| `datetime` | ISO-8601；RTC 未就绪时为 `-` |
| `in` / `out` | 累计进入 / 离开 |
| `occ` | 在场人数 = in − out |
| `q50_ms` / `q100_ms` | 两路队列探头本次连续遮挡时长 |
| `grade` | 0=较少 1=约半 2=全满 |
| `flags` | bit0 RTC 正常 / bit1 SD 正常 / bit2 交叉校验冲突 / bit3 探头疑似故障 / bit4 有可用历史（预测有效） |
| `pred` | 预测排队人数：过去 7 天同一 15 分钟时段的平均在场人数 |
| `pred_n` | 参与平均的天数；0 = 历史不足，此时 `pred` 为 0 |
| `beams` | 四路探头当前电平位图：bit0 入口A / bit1 入口B / bit2 队列50% / bit3 队列100%，1 = 遮挡 |

`pred` / `pred_n` / `beams` 是后加的字段：解析端按索引取字段，老固件少发这些字段时按 0 处理。

CRC8 用 **CRC-8/ATM**（poly 0x07，init 0x00，不反射），覆盖 `$` 之后到 `*` 之前，写成 2 位大写十六进制。两端实现必须一致：`core/protocol.c` 与 `esp32/qsm_monitor/serial_link.cpp`。

## 历史人数与 SD 长期存储

STM32 每 60 s 把当前在场人数记进 RAM 表（**7 天 × 96 个 15 分钟时段 = 672 B**），同时往 SD 卡追加一行：

```
文件名  HYYMMDD.CSV          例：H261109.CSV（8.3 短名，一天一个文件）
表头    HH:MM,occ
内容    12:30,12             每个 15 分钟时段一行，同段内后写覆盖先写
```

上电时把最近 8 天的这些文件读回 RAM 表，所以**断电不丢历史**。预测值 = 过去 7 天同一时段的平均在场人数（四舍五入），参与天数写进 `pred_n`。

设计取舍：

- **不含今天**：当天数据不完整，纳入会把平均拉低；连续跑满一个自然日后才有预测值。
- **要真实时间**：时段对齐依赖 DS3231，`APP_RTC_ENABLE = 0` 时预测恒为 0、网页显示"历史不足"。
- **一个时段存一个值**：不按分钟累积，只保留该时段最后一次读数，RAM 与文件都只有 96 行/天。
- **人数上限 254**：`0xFF` 用作"该时段无数据"的哨兵。

开关集中在 `stm32/App/app_config.h`：`APP_HISTORY_ENABLE`（预测）、`APP_HIST_PERSIST`（落卡）、`APP_RTC_ENABLE`、`APP_SDCARD_ENABLE`。

网页仪表板有"预测排队人数 / 参考天数"卡片，由 `/api/state` 的 `pred`、`predn` 驱动；
另有"四路探头实时状态"卡片（`beams` 字段）——挥手试每一支探头，手机上就能看出它是否被触发，
现场排查接线/供电时不用再接调试串口。

## 实时性与网页复位

- **上报 4 Hz**：`APP_TASK_REPORT_MS = 250`（`stm32/App/app_config.h`），
  网页每 **400 ms** 轮询 `/api/state`，探头遮挡/通光基本"抬手就变"；
  状态 CSV 与调试行仍是 1 Hz（`APP_TASK_STATUS_MS = 1000`），避免频繁写卡。
- **不需要按板子上的复位键**：网页提供三个按钮，下发的是一行命令帧（CRC 规则与上行帧一致）：

```
$QSR,<cmd>*<CRC8>\n
```

| cmd | 含义 | 网页按钮 |
|---|---|---|
| 1 | 计数与分级归零（`in`/`out`/`occ`/`grade`） | 清零计数 |
| 2 | 清空历史：RAM 表清零 + 删除 SD 卡最近 8 天的 `H*.CSV` | 清空历史 |
| 3 | 两者都做 | 全部复位 |

- STM32 侧用 **USART2 RX 中断**把字节收进环形缓冲，主循环 `bsp_uart_poll_cmd()` 非阻塞取整行、
  校验 CRC 后执行；串口异常或 RTC 掉线都不会把主循环卡住（I2C 连续 10 次读失败会自动做总线恢复）。
- **断流提示**：超过 2.5 s 没有新帧，网页顶部出现橙色"数据已 N 秒未更新 — STM32 可能没在发帧"，
  避免盯着一个"冻住"的页面误判为现场正常。

## 迭代路径（把 proposal 的内容接上来）

框架已经为后续升级留好接口，不需要重写：

1. **连续身高估计**：`queue_grade.c` 旁边新增 `queue_length.c`，同一份探头事件流可复用；`core/` 的纯逻辑分层的意义就在这里。
2. **等待时间模型（利特尔法则）**：新增 `waiting_time.c`，输入是已有 `count_in`（到达率）与连续长度，输出 `W = L/λ`；协议只需在帧尾追加字段（`protocol.c` 加一个字段即可，ESP32 端同步改 `serial_link.cpp`）。
3. **双通道融合**：若后续加回热阵列，`core/` 里再加一个 `thermal_count.c`，与 `queue_grade` 的输出在 `app_main` 里融合，两端协议不变。

## 已知限制

- 进出方向判定的准确率依赖两支探头的机械间距（建议 10 cm）与现场单列通行；并排通过仍会漏计，这一点与参考文献 [1] 的结论一致。
- 占用数是累加量，**误差会累积**；当前靠 `occ` 夹紧 ≥0 与交叉校验缓解，尚未实现空区归零（可作为 A4 长时运行的改进项）。
- 分级只反映"探头位置被持续遮挡"，不区分"排队"与"长时间停留"；`grade_sustain_ms` 的标定需要在现场用人工计数确定。
- 预测值只按"星期几 + 15 分钟时段"取平均，不识别节假日、天气与课程表；参与天数 `pred_n` 会如实显示，样本不足时仅供参考。
