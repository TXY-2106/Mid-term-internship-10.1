# firmware —— 排队状态监测器固件

按仓库 `README.md` 已确认的方案实现：**4 路 E18-D80NK 红外光电开关 + STM32F103C8T6 边缘采集 + ESP32 联网展示**，队列长度以**三级离散分级**（较少 / 约半 / 全满）表示。

> **范围**：本期不做连续人数与等待分钟数。`docs/proposal.md` 中的连续长度估计与利特尔法则等待时间模型，作为**后续迭代**（见文末「迭代路径」）。

## 目录结构

```
firmware/
├── core/                纯逻辑，无硬件依赖，可在 PC 上编译与单元测试
│   ├── qsm_types.h        共用类型、分级枚举、默认参数
│   ├── gate_counter.c/.h  双束方向判别 + 在场人数
│   ├── queue_grade.c/.h   持续遮挡计时 + 三级判定 + 滞回 + 交叉校验
│   └── protocol.c/.h      串口帧编解码 + CRC8
├── stm32/               目标固件（Keil MDK5 + 标准外设库）
│   ├── App/               参数集中、主流程、CSV 日志
│   └── BSP/               采样去抖、RTC、SD 卡、串口
├── esp32/qsm_monitor/   网关（Arduino IDE 草图工程）
└── tests/               core 的单元测试（gcc + make）
```

**为什么要单独分出 `core/`**：这部分才是真正的判定逻辑。把它与 HAL 解耦之后，可以脱离硬件在 PC 上跑测试——这正是验收标准 **A7「测试证据」** 最直接的来源，也避免"只能在板子上试出来"的调试困境。

## 数据流

```
E18 进出 ×2 ─┐
             ├─► STM32 ──SPI──► SD 卡（status.csv / events.csv）
E18 队列 ×2 ─┘      │
                    ├──I²C──► DS3231（离线时间戳）
                    └──UART──► ESP32 ──Wi-Fi──► 网页仪表板
```

两块板职责严格分离：**ESP32 掉线或重启，不影响 STM32 的采集与落盘**。

## 串口协议

单行 ASCII，115200 8N1，便于用任意串口助手肉眼调试：

```
$QSM,<seq>,<ms>,<datetime>,<in>,<out>,<occ>,<q50_ms>,<q100_ms>,<grade>,<flags>*<CRC8>\n
```

真实样例（由 `tests/` 编译出的编码器生成）：

```
$QSM,1024,3735000,2026-10-28T12:31:04,37,29,8,6100,0,2,3*51
```

| 字段 | 含义 |
|---|---|
| `seq` | 帧序号，掉帧可发现 |
| `ms` | STM32 开机毫秒 |
| `datetime` | ISO-8601；RTC 未就绪时为 `-` |
| `in` / `out` | 累计进入 / 离开 |
| `occ` | 在场人数 = in − out |
| `q50_ms` / `q100_ms` | 两路队列探头本次连续遮挡时长 |
| `grade` | 0=较少 1=约半 2=全满 |
| `flags` | bit0 RTC 正常 / bit1 SD 正常 / bit2 交叉校验冲突 / bit3 探头疑似故障 |

CRC8 用 **CRC-8/ATM**（poly 0x07，init 0x00，不反射），覆盖 `$` 之后到 `*` 之前。两端实现必须一致：`core/protocol.c` 与 `esp32/qsm_monitor/serial_link.cpp`。

## 与验收标准的对应

| 编号 | 本框架如何支撑 |
|---|---|
| A1 排队分级一致率 ≥80% | 分级逻辑在 `queue_grade.c`，阈值全在 `app_config.h`，可逐项标定；`events.csv` 支持事后复核 |
| A2 拥挤状态判定 ≥80% | 分级 + 在场人数 + 进出流量三类输入齐备（对应 A6） |
| A3 端到端 ≤5 s | STM32 每 1 s 上报，网页每 1 s 轮询，实测余量充足 |
| A4 稳定 4 h 无丢数 | 事件写卡 + 10 s `f_sync`；`seq` 字段可查掉帧 |
| A5 隐私合规 | 全系统无成像器件，仅聚合计数 |
| A6 至少 2 类输入 | 进出流量 + 队列阈值探头（共 4 路） |
| A7 测试证据 | `tests/` 可重复运行；`events.csv` / `status.csv` 为原始数据 |
| A8 仪表板 | ESP32 内嵌网页，实时状态 + 趋势 + 告警 |
| A9 跨国复制 | 全部器件为通用件，引脚与参数集中可改 |

## 迭代路径（把 proposal 的内容接上来）

框架已经为后续升级留好接口，不需要重写：

1. **连续身高估计**：`queue_grade.c` 旁边新增 `queue_length.c`，同一份探头事件流可复用；`core/` 的纯逻辑分层的意义就在这里。
2. **等待时间模型（利特尔法则）**：新增 `waiting_time.c`，输入是已有 `count_in`（到达率）与连续长度，输出 `W = L/λ`；协议只需在帧尾追加字段（`protocol.c` 加一个字段即可，ESP32 端同步改 `serial_link.cpp`）。
3. **双通道融合**：若后续加回热阵列，`core/` 里再加一个 `thermal_count.c`，与 `queue_grade` 的输出了在 `app_main` 里融合，两端协议不变。

## 已知限制

- 进出方向判定的准确率依赖两支探头的机械间距（建议 10 cm）与现场单列通行；并排通过仍会漏计，这一点与参考文献 [1] 的结论一致。
- 占用数是累加量，**误差会累积**；当前靠 `occ` 夹紧 ≥0 与交叉校验缓解，尚未实现空区归零（可作为 A4 长时运行的改进项）。
- 分级只反映"探头位置被持续遮挡"，不区分"排队"与"长时间停留"；`grade_sustain_ms` 的标定需要在现场用人工计数确定。
